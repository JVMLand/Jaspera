# 性能測定（2026-09-07）

## 条件

Windows / Edge headless、本番ビルドを localhost で配信。変更前は `a164391`、変更後は本記録と同時に保存した最適化を適用。各3回、新しいブラウザコンテキストで測定した。ネットワーク転送速度や実機での描画の滑らかさを測るものではない。

初期解析が終わってから Hello World を2回実行し、20 / 200 / 1,000 個の `nop` と `return` からなるメソッドを順に解析。同じソースのキャッシュ取得も測定した。解析には構文解析、検証、フレーム・グラフ情報と class の生成、Worker 通信を含む。分岐や複雑な型を含む実際のコードでは結果は異なる。

## 結果（中央値）

| 入力 | 変更前 | 変更後 | 短縮率 |
| --- | ---: | ---: | ---: |
| 21 命令 | 361.6 ms | 198.9 ms | 45.0% |
| 201 命令 | 3596.8 ms | 1909.6 ms | 46.9% |
| 1001 命令 | 25783.2 ms | 12377.6 ms | 52.0% |

起動から実行可能になるまで: 3172 → 3033 ms。Hello World 実行（各6回）: 2326 → 2366 ms。起動時間の差は小さく、実行時間には改善を確認できなかった。

Graph を一度も開いていない状態では、Worker が4個から2個になり、グラフのノード生成数は4個から0個になった。同じ解析結果のキャッシュ取得は前後とも0〜0.1 ms。解析結果の JSON サイズも前後で同じ（6,620 / 61,634 / 308,976 bytes）。

## 変更

- 診断のために作った構文木をコンパイルでも利用し、2回目の前処理・構文解析を省略。
- ブラウザでは出力しない解析ログの文字列・配列生成を抑制。警告・エラーや型検証は残す。
- JSON の Unicode エスケープで文字ごとの `String.format` を廃止。
- 解析キューで、開始前に新しい版へ置き換わった要求を省略。実行中の解析と同じ版の共有は維持。
- 非表示の Graph / Instructions は初回表示まで生成を遅らせ、非表示中の更新は最新の状態を保持。すでに開始した処理の強制中断はしない。
- Instructions の検索で選択命令が変わらなければ、説明・サンプル用エディタを再生成しない。
- 小窓の同期から全状態の JSON 比較を除去。Console は追加分を挿入し、Problems は診断が変わったときだけ更新。
- カーソル移動時は文書の版が同じならソース文字列を取り直さない。

## 残る負荷

コンパイルは引き続きメソッド全体を解析する。1,001命令の単純なコードでも約12秒を要し、巨大メソッドの解析には改善余地がある。実行ごとの JVM 初期化やメイン JS のサイズも今回の変更では減らしていない。

## 確認

解析キュー、ASM の診断位置、フレーム、グラフ、マクロ、構文エラー、全 UTF-16 コード単位の JSON 往復をテスト。ブラウザでは202命令の使用例、Graph の非表示・再表示、検索中のサンプル保持、テーマ、小窓の同期を確認した。
